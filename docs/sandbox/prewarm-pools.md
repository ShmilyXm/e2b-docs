# 预热池

预热池（Prewarm Pool）会提前为指定模板创建一组可用的 Sandbox。业务发起创建请求时，可以直接分配已经准备好的实例，从而降低对启动延迟敏感场景的等待时间。

预热池会持续维持设定的可用数量。实例被分配后，系统会自动补充新的预热实例。

:::warning 并发额度
处于空闲状态的预热 Sandbox 也会占用团队的并发 Sandbox 额度。请根据实际流量设置数量，并为正常业务实例预留足够额度。
:::

:::info 适用请求
当前实现只会把与池中实例配置兼容的普通创建请求分配到预热池。带有 Metadata、安全 Envd、自定义网络、Volume、自动暂停或自动恢复等额外配置的请求可能绕过预热池并按正常路径创建，以避免返回配置不一致的 Sandbox。Template 配置了默认 Volume 挂载时也应先验证是否能够命中预热池。
:::

## 创建预热池

1. 登录 E2B Dashboard。
2. 在左侧导航进入 **Operations → Prewarm pools**。
3. 单击 **Create pool**。
4. 填写预热池配置。
5. 确认配置后创建，等待状态变为 `ready`。

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 1～64 个字符，只能包含字母、数字、下划线、英文句点和连字符。 |
| Template | 是 | 预热 Sandbox 使用的模板。创建后不能更换。 |
| 预热数量 | 是 | 需要持续保持可用的 Sandbox 数量，范围为 1～100。 |
| 描述 | 否 | 预热池用途说明，最多 200 个字符。 |

:::info 固定模板构建版本
创建预热池时，系统会解析并固定当前模板构建版本。之后即使同一模板产生了新构建，现有预热池也不会自动切换版本。如需使用新构建，请创建新的预热池。
:::

## 查看运行状态

预热池列表中的 **Ready** 显示为 `当前可用数 / 目标数量`。Dashboard 会定期刷新数据。

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| `initializing` | 正在创建预热实例并填充池。 | 等待可用数达到目标数量。 |
| `ready` | 预热池已达到期望的可用数量。 | 无需处理。 |
| `degraded` | 系统暂时无法维持目标数量。 | 查看错误信息，并检查并发额度、模板构建和基础设施状态。 |

预热实例被业务分配后，**Ready** 数量可能短暂下降；系统完成补充后会恢复到目标数量。

## 调整预热数量

打开预热池后可以修改名称、预热数量和描述。建议根据高峰期创建速率逐步调整：

- 数量过小，突发请求仍可能等待 Sandbox 冷启动。
- 数量过大，会持续占用并发额度和计算资源。
- 模板或构建版本需要变化时，应新建预热池，不能通过编辑现有预热池完成。
- 业务创建请求经常携带高级配置时，应先通过监控确认实际命中率，再决定预热数量。

## 删除预热池

删除预热池会停止池内仍处于空闲状态的 Sandbox。已经分配给业务的 Sandbox 不受影响，会继续按自身生命周期运行。

删除前请确认业务已不再依赖该预热池。该操作不会删除关联的 Template。

## 常见问题

### 状态一直停留在 `initializing`

检查团队是否有足够的并发 Sandbox 额度，并确认模板构建可以正常启动。如果目标数量接近并发上限，预热池可能无法完成填充。

### 状态变为 `degraded`

优先查看预热池显示的最近一次错误。常见原因包括并发额度不足、模板构建不可用，或节点资源暂时不足。修复问题后，系统会继续尝试补充实例。

### 更新模板后为什么仍启动旧版本

预热池固定使用创建时解析出的模板构建版本。需要先创建指向新构建的预热池，验证可用后再删除旧池。
